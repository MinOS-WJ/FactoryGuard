# 维护手册

## 1. 日常检查

- 工作台在线率；
- 离线摄像头数量；
- 未关闭高危险情；
- 托盘是否仍在运行；
- 配置文件是否可读写；
- 磁盘剩余空间。

## 2. 备份

建议每日或变更前备份：

```text
config/factoryguard.json
data/factoryguard.db
events-media/
```

可使用文件复制或 Windows 任务计划。备份配置后再备份数据库，保证设备和凭据一致。

## 3. 配置变更

1. 停止或让程序进入托盘状态；
2. 备份配置；
3. 修改 `config/factoryguard.json`；
4. 重新启动或从托盘重启；
5. 在“系统设置”检查状态；
6. 记录变更内容。

## 4. 配置文件损坏时的恢复

配置文件 `config/factoryguard.json` 损坏时，程序无法启动，但业务数据仍在数据库中，不会丢失。启动提示会给出：

- 配置文件的完整路径；
- 可用的备份包列表；
- 恢复步骤。

恢复方式二选一：

1. 打开提示中列出的备份包，用界面“恢复备份”功能还原；
2. 手工把配置文件修正为合法 JSON 对象（顶层必须是对象），再重新启动。

## 5. 数据库维护

- 数据库只保存业务数据；
- 不建议手工修改 `data/factoryguard.db`；
- 升级前保留数据库副本；
- 若数据库损坏，从最近备份恢复；
- 事件媒体存在时随数据库一并备份。

## 6. 配置迁移

首次使用新版本时，程序会尝试把旧注册表中的 LLM/GB 设置和旧数据库凭据迁移到 JSON。迁移成功后：

- 新配置写入 `config/factoryguard.json`；
- 旧凭据从数据库删除；
- 旧 MerchantConsole 注册表项被清空；
- 迁移失败不会删除旧数据，可按日志手工迁移。

## 7. 线程与进程

如发现关闭窗口后没有托盘图标：

- 检查 Windows 通知区域隐藏图标；
- 使用任务管理器确认进程是否仍在；
- 在托盘菜单使用“退出 FactoryGuard”；
- 不要直接结束异常进程，除非程序无响应。

## 8. 日志与诊断

- 状态栏显示最近一次刷新结果；
- 设备健康详情显示在摄像头状态提示中；
- `python src/main.py health --db ... --media-dir ...` 可做命令行预检；
  整机 CPU 占用偏高只提示警告（多半是其他程序在跑），只有磁盘空间不足或内存耗尽才会判定失败；
- 诊断输出中不得粘贴明文密码或 API Key。

## 9. 升级流程

1. 备份配置、数据库和媒体；
2. 更新代码与依赖；
3. 运行 `python -m pytest -q`；
4. 启动程序检查启动画面和托盘；
5. 打开一个摄像头确认播放；
6. 创建并处理一条测试险情；
7. 确认无误后投入正式使用。

## 10. 已知限制

- 单进程、小规模本地部署；
- 明文配置文件需要人工保护；
- 不负责 NVR 录像存储；
- 真实 ONVIF/GB28181 兼容性需要现场确认；
- 暂未提供安装包、服务化部署和自动升级。

# FactoryGuard 智守需求分析

## 1. 背景

FactoryGuard 是面向商户、物业和安保人员的小规模多区域视频安防平台，重点是视频设备接入、区域组织、险情处置、大语言模型文本问询和后台值守。视觉侧不加载模型，也不对视频帧执行推理。

## 2. 产品目标

1. 让非技术用户能够完成摄像头接入和日常查看；
2. 将多摄像头、多区域与险情统一到一个工作台；
3. 通过可选大语言模型增强自然语言问询和险情登记；
4. 软件配置与业务数据分离，配置使用可编辑 JSON 文件；
5. 支持一键导出备份、查看备份数量和最近时间，并在下次启动前安全校验和恢复；未来主版本备份必须拒绝恢复；
5. 启动后可在系统托盘后台常驻，不因关闭窗口停止值守；
6. 小规模本地部署无需外部数据库或云平台即可运行。

## 3. 目标用户

| 用户 | 核心任务 | 使用特点 |
| --- | --- | --- |
| 商户店主 | 查看门店、仓库和出入口 | 不熟悉网络与设备参数，需要明确引导 |
| 物业值班员 | 查看告警、登记险情、跟踪处理 | 需要高效率、低学习成本 |
| 安保负责人 | 汇总区域态势、处置高危险情 | 关注优先级、责任与记录 |
| 实施人员 | 接入 ONVIF、GB/T 28181、RTSP | 关注协议兼容、诊断和可维护性 |

## 4. 功能需求

### FR-01 场所、区域与摄像头

- 支持场所和区域层级；
- 同一区域支持多台摄像头；
- 摄像头支持 ONVIF、GB/T 28181、RTSP 接入；
- SIP 服务启动必须等待实际端口绑定结果，启动失败或运行中退出需在界面明确提示；
- 支持在线、离线、待检测状态；
- 支持编辑摄像头名称、区域和连接参数；
- 支持暂停/恢复摄像头接入，暂停期间不取流、不生成设备险情；
- 支持删除摄像头，历史险情记录不丢失；
- 支持重命名空区域及删除空区域；
- 添加摄像头时阻止同协议、同设备通道或同 RTSP 地址重复接入；
- 支持按区域、状态和关键词筛选；
- 摄像头卡片和运营快照显示最近状态检测时间；
- 启动 60 秒后首次检测启用码流，之后每 10 分钟自动检测，手动检测可随时触发。

### FR-02 实时视频

- 点击摄像头进入单路实时画面；
- 可从当前筛选结果中选择最多四路摄像头同屏查看；超过四路时打开画面选择器；
- 关闭多路画面墙时停止全部对应解码任务；
- 单路预览采用较高帧率，多路画面墙采用适配多路并发的分辨率与帧率；
- 视频仅解码显示，不启动视觉推理；
- 断开视频时给出明确状态，并提供单路预览和画面墙单格重新连接；
- 不在界面显示摄像头账号密码。

### FR-03 险情管理

- 支持用户手动上报；
- 支持现场问询自然语言登记；
- 支持高危、关注、提示等级；
- 支持待处理、处理中、已解决、误报状态；
- 已解决或误报险情可确认后重新打开，并记录状态纠错审计；
- ONVIF PullPoint 与 GB/T 28181 原生告警在约 1 秒内进入险情队列并给出托盘/任务栏提醒；
- 连续 ONVIF 告警按设备、主题、时间、通道和事件数据生成稳定唯一标识，不因相同 PropertyOperation 或不同设备复用事件号被误去重；
- 运营上下文始终包含全部未关闭险情，并附带最近 100 条历史险情，避免旧未关闭记录被大量已解决记录挤出；
- 内存事件去重缓存设有上限，长期运行不会无限增长；
- 摄像头状态检测与实时预览使用同一最佳码流，避免显示在线但实际无法播放；
- 摄像头卡片可查看告警订阅异常原因；
- 记录区域、摄像头、来源、上报人、时间和处置审计；
- 险情详情展示最近处置记录，包括操作人、本地时间和状态变化；通知详情与备份创建时间同样使用本机时区。

### FR-04 现场问询

- 支持查询摄像头、区域、设备、险情和最近事件；
- 未配置大模型时使用本地规则问答；
- 可配置 OpenAI Chat Completions 兼容接口；
- 支持服务商、地址、模型、密钥、超时和独立启停；
- 大模型不可用时自动回退本地规则；
- 运营快照不包含原始视频或配置文件中的敏感字段。

### FR-05 软件配置

- 软件设置集中保存在 `config/factoryguard.json`；
- 支持 `--config` 和 `FACTORYGUARD_CONFIG` 指定配置路径；
- 配置可手工查看和编辑；
- 当前小规模部署不启用额外加密，密钥以明文保存在本地配置文件；
- 默认不预填服务商、接口、模型、国标平台编号和 SIP 域，由客户按现场配置；
- 数据库不得承担软件设置、模型参数、国标参数或设备凭据存储。

### FR-06 启动与后台常驻

- 同一 Windows 用户只允许运行一个实例，重复启动提示从现有托盘窗口进入；
- 启动时显示品牌启动画面和初始化进度；
- 初始化完成后进入商户工作台；
- 关闭窗口时隐藏到系统托盘并继续运行；
- 托盘菜单支持打开控制台、上报险情、刷新状态和退出；
- 自动化环境可通过环境变量禁用托盘。

### FR-07 品牌横幅

- 软件顶部始终显示完整的默认品牌横幅，不出现空白占位；
- 允许客户提供自己的 SVG 横幅并整条替换默认横幅；
- 支持在设置页选择、预览、调整高度、保存和恢复默认；
- SVG 自动等比铺满可用区域，不拉伸变形；
- 拒绝无效 SVG、包含脚本的 SVG 以及超过 5 MB 的文件；
- SVG 文件复制到配置目录，相对路径写入 JSON 配置文件。

### FR-08 险情通知

- 用户可在系统设置中独立启用 Webhook、SMTP 邮件和短信网关通知；
- 手动上报、问询登记和 ONVIF/GB 原生告警产生的新险情均可异步发送；
- Webhook 支持 HMAC-SHA256 请求签名；
- 设置页支持发送测试通知并在不丢失已保存密码的前提下更新配置；
- 每次通知渠道结果和尝试次数写入业务数据库，并在险情详情中展示；
- 支持仅重试失败的渠道，避免重复发送成功通知；
- 对失败超过 60 秒且尝试未满 3 次的渠道自动退避重试；
- 通知失败只在状态栏提示，不阻断险情保存和处置；
- 通知配置保存在 JSON 配置文件，不写入 SQLite。

### FR-09 多摄像头模拟工具

- 支持一次启动多台虚拟摄像头；
- 模拟 ONVIF Profile S 设备服务、通道枚举与 RTSP 码流；
- 模拟 GB/T 28181 注册、Digest 认证、目录、Keepalive、告警和实时点播；
- 提供多客户端同时观看的 RTSP 测试画面和 JSON 端点输出；
- 仅用于本地联调、自动化测试和培训，不作为生产设备。

## 5. 非功能需求

| 编号 | 要求 |
| --- | --- |
| NFR-01 | 目标环境为 Windows 10/11，最小窗口 1120×640，兼容 1366×768 在 125% 缩放下的逻辑分辨率 |
| NFR-02 | 典型场景为 4～32 路摄像头，小规模单机部署 |
| NFR-03 | 配置和业务数据均保存在本机 |
| NFR-04 | 关闭窗口后后台服务继续运行，用户必须显式退出 |
| NFR-05 | 摄像头密码不出现在运营快照、界面日志或诊断输出中 |
| NFR-06 | 配置文件损坏时启动给出明确错误，不静默覆盖 |
| NFR-07 | 后台线程在窗口关闭、视频断开和退出时必须安全清理 |
| NFR-08 | 单元与集成测试须覆盖配置、险情、问询、线程、品牌横幅和 UI 主流程 |
| NFR-09 | 源码须通过 Ruff 静态检查、Ruff 格式检查和 Python 编译检查 |

## 6. 边界与非目标

- 不承担 7×24 录像存储，录像仍由 NVR 或摄像头负责；
- 不提供视觉模型、目标检测和画面推理功能；
- 当前不实现多租户、云端集中管理和跨组织权限；
- 当前不保证多进程同时写同一配置文件或业务数据库；
- GB/T 28181 上下级平台级联不在当前范围；
- 真实设备型号兼容性需现场联调确认；
- 模拟器不覆盖 PTZ、录像回放、云台控制和厂商私有扩展，也不能替代真实设备联调。

## 7. 关键假设

- 用户设备位于可信局域网；
- 部署电脑由单一用户或单一值守团队使用；
- 摄像头、NVR 和编码器提供标准 ONVIF、GB/T 28181 或 RTSP 能力；
- 小规模用户可接受本地明文配置文件，并通过操作系统权限保护电脑和目录。

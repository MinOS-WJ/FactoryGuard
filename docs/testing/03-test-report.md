## 5. 重点覆盖

- JSON 配置读写、嵌套字段递归合并、写失败回滚、LLM 配置持久化，以及旧配置迁移时保留现有设置并安全转移凭据；
- 商户控制台六页面、1280/1366/1440 多分辨率无水平溢出；
- 摄像头和区域管理：原子保存、凭据回滚、编辑、删除、父级校验、非空区域保护、历史险情保留；
- 默认横幅、客户 SVG、脚本拒绝和恢复默认；
- 退出时等待后台线程，完成后关闭 SQLite；
- ONVIF 多设备扫描选择、目标地址预填和取消行为；
- 纯视频预览 API 不提供检测框、置信度、目标标签或检测截图能力；
- 领域模型只保留设备原生告警码、去重和动作路由，不再定义目标框、置信度、轨迹、画面几何或条件树；
- 内置规则模板已改为 ONVIF/GB28181 原生告警码模板，旧视觉规则评估和模拟入口调用即明确禁用；
- ONVIF 探测、通道和 RTSP 首帧；
- GB/T 28181 注册、目录、告警、INVITE 后 RTP 首帧；
- RTSP 连接测试和分辨率回报；
- Webhook HMAC-SHA256 签名、SMTP 邮件、短信网关和 JSON 配置持久化；
- 通知投递结果持久化、尝试次数、业务化渠道名称、失败原因展示、失败渠道单独重试和通知任务异常自动进入重试；
- 单个通知渠道异常隔离，避免拖垮其他渠道；
- 险情搜索可匹配区域、摄像头、等级、状态和来源；问询摘要和引用统一使用险情表记录；
- 设置页数字输入、区域待检测状态和运维健康检查的产品语义；
- 配置文件写入失败时内存状态回滚；
- HTTP 错误响应统一关闭，避免长时间运行累积未释放套接字；
- 单实例运行、后台任务防重入和周期刷新性能；
- 通知表单按总开关和渠道开关逐级启用；
- ONVIF 原生事件订阅、能力探测、连续事件唯一指纹和订阅健康展示；
- 设备原生事件策略、事件去重和通知分发；
- 险情创建、筛选、状态流转、对话历史，以及超过 100 条近期关闭记录后未关闭险情仍保留；
- 大语言模型可选增强、本地规则回退、重复险情抑制和 API Key 错误脱敏；
- 当前 CLI 只暴露业务与运维命令，视觉模型参数被拒绝；
- 模型目录、推理代码和推理依赖不存在。

| 添加摄像头向导只有 RTSP 能测试连接，ONVIF 填完地址只能保存后才知道对错 | 新增 ONVIF 连接测试：校验地址与账号、显示认证结果与视频通道数量，失败给出原因；国标仍按平台注册流程检测 |
| 缓存码流只按主机名判断是否复用，设备改到同主机不同端口后预览仍连接旧地址 | 主机相同但端口不同时判定为不匹配，改址后强制重新解析码流 |
| 场所（门店）没有独立管理入口，只能新建区域时顺带创建；改门店名或撤店需删光区域重来，摄像头配置全部丢失 | 新增场所的新建、重命名与删除：设备页顶部列出各场所及区域/摄像头数量并可直接管理，删除前校验场所下无区域 |
| 险情记录没有导出入口，商户向物业或保险提交报告只能截图 | 险情中心新增“导出清单”，导出当前筛选结果为 UTF-8 BOM 的 CSV，包含地点、等级、状态、上报人、处置记录，Excel 可直接打开 |
| 险情通知连续失败 3 次后永久放弃重试，网络临时中断会导致告警永久丢失 | 取消硬性次数上限，改为按失败次数指数退避（最长 1 小时），只要渠道仍在启用就持续补发 |
| 险情中心只加载最近 100 条记录，搜索三个月前的记录无结果且无任何提示 | 输入搜索词时从数据库检索全量历史，区域、摄像头、状态与地点快照均可匹配 |
| 通知失败重试不区分险情状态，已标记误报的历史险情仍会持续补发通知 | 自动补发只针对未关闭险情；已解决或误报的停止自动重试，但仍可手动重试并查看失败原因 |
| 险情只快照区域和摄像头名称，场所改名或撤店后导出报告的场所列会为空 | 险情同时快照场所名称，导出与界面在场所变动后仍显示事发当时的完整地点 |
| 界面列表显示区域的新名称、导出显示事发当时的旧名称，同一条记录两处口径不一致 | 界面与导出统一使用事发时记录的地点快照，区域改名不影响历史记录的呈现 |
| 国标告警的通道号带 `:ss` 后缀而目录为纯编号，精确匹配导致告警无法归属到摄像头 | 匹配前规范化国标通道号（去掉后缀），告警能落到正确摄像头；导入去重同样规范化 |
| 问询回答把所有离线摄像头和险情一次性铺开，且不提示去哪里处理 | 离线列表最多显示 6 条并给出总数，险情摘要说明剩余条数，两类回答都指向可处理的具体页面 |
| 配置文件写入使用固定临时文件名，多个写入者互相替换对方半写好的文件，可能丢配置 | 临时文件名加入进程号与随机串，并发写入互不干扰且不残留临时文件 |
| 险情搜索每次都把全部历史读入内存再过滤，数据量大时每敲一键都重载 | 数据库先按关键词收窄，再按拓扑标签确认或回退，命中范围与结果不变 |
| 数据库损坏时启动提示只让用户检查权限、磁盘和占用，真正原因没提 | 按失败原因分别给出指引：数据损坏给出改名保留与恢复备份步骤，文件被占用提示关闭其他实例 |
| 实时画面只能按区域筛选，多门店时无法快速查看某个门店的全部设备；离线摘要也不带场所 | 新增场所筛选器并与区域筛选联动；离线摘要显示“场所的摄像头” |
| 处置流程无法填写现场说明，商户只能改状态；审计里虽存了备注但界面不展示 | 详情页新增处置说明输入框，备注随状态变更写入审计并显示在处置记录与导出清单中 |
| 模拟器的跨进程 CLI 方式缺少端到端验证，文档流程是否可用只能靠人工确认 | 新增跨进程用例：按文档启动模拟器，平台真实完成 ONVIF 认证、发现通道并取得 RTSP 码流地址；国标链路同样验证注册、目录与告警送达 |

## 8. 已知限制与未验证范围

- 旧 SQLite 库中的视觉规则兼容列仍保留以避免破坏历史数据，但不再读取为业务字段、不再导出为画面规则；
- 真实 ONVIF/GB28181 摄像头型号兼容性必须现场联调；
- ONVIF WS-Discovery 在目标局域网的 UDP 3702 多播和防火墙行为仍需验证；
- 国标模拟器每设备单通道，不覆盖平台级联、PTZ 和录像回放；
- RTSP 模拟器是联调用的最小兼容实现；
- Windows 托盘、通知和开机启动需在目标机器复核；
- 4～32 路摄像头长时间并发和断网恢复仍需压力测试；
- 安装包、代码签名和升级回滚不在本轮自动化范围。

## 9. 发布建议

建议先进行受控试运行：

1. 在目标 Windows 11 机器复核中文、托盘、启动画面和客户 SVG；
2. 使用至少一台 ONVIF、一台 RTSP、一台 GB/T 28181 设备联调；
3. 验证真实设备告警到险情和通知的完整链路；
4. 完成配置、品牌素材和业务数据库的备份恢复演练；
5. 记录设备型号、固件、网络环境和兼容性结果。
